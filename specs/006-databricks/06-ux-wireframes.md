# 06 · UX, wireframes and navigation

[Index](README.md) · prev: [05 Data model](05-data-model-lakebase.md) · next: [07 Choosing the model](07-model-selection.md)

Every screen here is generated by [`tools/wireframes.py`](tools/wireframes.py) on a fixed character
grid, so a border cannot drift: `npm run verify:spec-006` re-checks alignment, and
`python3 tools/wireframes.py --check` re-checks it without node. The screens are the *contract*; the
prose under each one says what it commits us to.

---

## The navigation model

Three zones, one document model, five ways in. The rule that makes this coherent: **every entry point
produces the same `Doc`, and the focus is derived from it** — so no two surfaces can disagree about
what is open.

Every state names a next action. A failure keeps the turn's model pin and offers the only two
things that can help: retry, or a different model.

## What each screen commits us to

### Screen 1 — Today

The transcript is replaced, not moved: `turnsRendered` is 0 with a document open ([01 N1](01-current-state-audit.md#n1-the-conversation-is-not-on-screen-when-a-document-is-open)).
The right column says `session FACTS only` because that is literally what `Inspector` renders
([`Chrome.tsx:51-128`](../../apps/coding-agent/web/src/components/Chrome.tsx)).

### Screen 2 — Target

Four details carry the design, and each is a requirement:

| Detail | Requirement | Why it is drawn this way |
|---|---|---|
| `in context: display_unity_cat…` | AD-6 | Genie Code's chip names the file; ours must too, and it must be *the* binding rather than a label. |
| The tool calls (`▸ read_notebook 4.2s done`) are in the dock, collapsed | AD-7 | A transcript with tool calls at 380 px must not push the answer off screen. |
| `⏸ approval: write outside` inline | AD-8 | A modal over the code is the defect being fixed. |
| `model ▾ flash-3.8  ⌘⇧M` under the composer | MC-3 | The model is where you type, not only where you look. |

### Screen 3 — Narrow

`⌘J` is printed on the document bar. That is the discoverability answer for P3: a key nobody can see
is not a feature. The dock is closed by default at this width and never opens on resize (AD-4).

### Screen 4 — The four states

The failure state keeps `the turn kept its pin`: a failed turn must not silently change which model
the next one will use. That is [005 FR-9](../005-llm-models/02-requirements.md) rendered as UI.

### Screen 5 — The model

Two triggers, one popover. The popover is the existing 005 picker, unchanged, which is why MC-2 is a
DRY requirement rather than a design one.

### Screen 6 — Files as a list

The columns are the ones that answer "which one": type tells you what will open, owner tells you
whose it is, updated tells you whether it is the one you were editing. Tree stays for *where*.

### Screen 7 — Navigation

Five doors, one `Doc`. This is the diagram that makes FX-1 testable: if two doors can produce
different `Doc`s for the same object, the diagram is wrong and the code with it.

## States, for each new surface

A screen is not specified until its empty, loading, error and narrow cases are.

### The dock

| State | Header | Body | Keyboard |
|---|---|---|---|
| empty, no session | `New conversation` | three suggestions for the focus | `⏎` on a focused suggestion sends |
| empty, session exists | `New conversation` | the previous turns, or suggestions if none | `⌘L` focuses the composer |
| streaming | `in context: …` | turns + live answer | `Esc` stops; `⌘J` hides without stopping |
| asking | `needs your decision` | the approval inline | `⌘⏎` allows once, `Esc`… **does not deny** — a refusal must be deliberate |
| failed | `that turn failed` | the provider's words, the pinned model | `⌘R` retries |
| disconnected | `reconnecting…` | the last known turns, dimmed | automatic |

The `asking` row contains a deliberate asymmetry: **`Esc` never denies**. Dismissing a dialog by
accident must not refuse an action the user may have wanted; the three outcomes are buttons.

### Files

| State | Tree | List |
|---|---|---|
| loading | skeleton rows, `aria-busy` | skeleton rows |
| empty folder | `(empty)` in place | `No items here` plus a Create button |
| unreadable | `PaneError` with the reason, in place of the folder's children | a banner above the list |
| searching | skeleton + the existing slow hint | same |
| error | `PaneError` + `Try again` | same |

### The model control

| State | Trigger | Popover |
|---|---|---|
| no catalogue yet | `model · loading` disabled | — |
| models available | `model ▾ <label>` with a state glyph | grouped, searchable |
| current model unavailable | `model ▾ <label>` + warning glyph | the row states the remedy |
| no models at all | `model · none` | explains that the gateway is unreachable |
| switch in flight | trigger `aria-busy`, label unchanged | rows disabled |

## Density and type

The dock is new chrome, so it must not invent a second scale. It reuses the existing tokens:

| Element | Token | Value |
|---|---|---|
| dock header height | — | 40 px, the same as `.doc-bar` ([`styles.css:1137-1140`](../../apps/coding-agent/web/src/styles.css)) |
| body padding | — | 12 px 14 px, slightly tighter than the centre's 22 px 28 px, because the column is narrower |
| turn text | `--fs-13` | 13 px, the transcript's body size |
| tool row | `--mono` | 11.5 px |
| composer | `.composer` | the same component, `variant="dock"` |
| state chip | `.pill` | the existing pill |

**No new colours.** The dock uses `--surface`, `--line`, `--ink-2`, `--blue-600` exactly as the
transcript does. A new panel with a new tint is how an app starts looking assembled rather than
designed.

## Accessibility contract

| Requirement | Implementation | Test |
|---|---|---|
| The dock is a landmark | `<aside aria-label="Assistant">` | a11y audit |
| The toggle states its state | `aria-pressed` + a name that changes | a11y audit at 1600 and 760 |
| Tokens are not announced per token | one `aria-live="polite"` region per **completed** answer | unit test on the announce policy |
| An approval is announced once | `role="alert"` on the inline panel, not on the wrapper | a11y audit |
| Focus returns from the drawer | `onClose` focuses the toggle | e2e AD-10 |
| Every action is reachable without a mouse | palette entries for dock toggle, model, files list/tree | palette unit test |
| Contrast | existing tokens, already audited by `audit:a11y` | `npm run audit:a11y` |
| Reduced motion | the drawer respects `prefers-reduced-motion` like the existing drawers | `audit:a11y` |

## Copy: the words on the surface

Wording is part of the design, because a wrong sentence costs more than a wrong border.

| Where | Instead of | Say |
|---|---|---|
| dock, no session | "Start a conversation" | `New conversation` + the focus chip |
| dock, nothing open | "No context" | `in context: nothing open` — and the suggestions name an action |
| a switch | "Model updated" | `Switched to <model>. Applies to your next message.` (existing copy, kept) |
| a failed turn | "Something went wrong" | the provider's own words, then `Retry` or `Change model` |
| an approval in the dock | "Permission required" | `needs your decision` — and the target is named |
| the drawer toggle | "Toggle panel" | `Show the assistant (⌘J)` / `Hide the assistant (⌘J)` |
| Files, empty | "Nothing here" | `No items in this folder` + `Create` |

The rule: **a state names the next action, or it is not a state.** "Something went wrong" is not a
state; it is an abdication.
