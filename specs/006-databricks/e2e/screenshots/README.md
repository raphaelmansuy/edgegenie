# Screenshots

Generated by `web/scripts/dock-shots.mjs` and `web/scripts/dock-e2e.mjs` against a running app.
Every image here was opened and inspected while the work was done; a screenshot nobody looked at is a
screenshot that lies.

## `screenshots/` — the shell at four widths

One folder pass per width, six states each. The script drives the app the way a person does: it sends
a prompt, opens a file, opens the model picker, presses `⌘J`, and switches Files to the list.

## `scenes/` — the e2e report and its evidence

`report.json` is the machine-readable result of the 30 checks in `web/scripts/dock-e2e.mjs`; the PNGs
are the screenshots those scenes took. `04-cell-bound.png` is the one to read first: it shows
`in context: bar_notes · cell 1` with the cell's `ask` action, which is the "update a file in context"
interaction the whole spec exists for.

## Two things these images show that the code review would not

1. **The scrim used to cover the model control at 1024 px.** The assistant drawer is the surface the
   user is working in, so dimming the document behind it also dimmed the control they need. The e2e
   caught it (scene 7); the fix is that only the rail and the inspector drawers take a scrim.
2. **A grid child with `min-width: 0` and no content resolves to 1 px.** The dock rendered at
   `width: 1` until it was given an explicit `justify-self: stretch`. Visible only by measuring.

## What these images deliberately do not show

A real model's answer. These runs use the fake agent (`APP_AGENT_MODE=fake`), so the tool calls and
the notebook name (`taxi_hours`) are scripted. The *layout* is what is being evidenced here; the
agent's behaviour is evidenced in `../e2e/before/` and in the app's own runbook.
