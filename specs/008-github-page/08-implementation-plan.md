# 08. Implementation plan

[Index](README.md) · prev: [07 Architecture](07-architecture.md) · next: [09 Edge cases](09-edge-cases.md)

Seven phases. Each has a deliverable, an acceptance criterion that can fail, and the requirement ids it
closes. The order is dependency order: nothing in a phase starts before the phase before it produces
something checkable.

| Phase | Deliverable | Closes | Acceptance |
|---|---|---|---|
| P1 | `LICENSE`, rewritten `README.md` | `PG-1`, `PG-12` | The README's first screen answers what, why, licence, screenshot |
| P2 | `site/claims.py` + tests | `CPT-1`…`CPT-8` | `python3 site/claims.py` prints eight claims; a test asserts each against `exams/make_tables.py` |
| P3 | `site/mdrender.py`, `site/pages.py`, `site/build.py` | `PG-4`, `NAV-1`, `SEO-1` | Eight routes build; two runs are byte-identical (`PG-11`) |
| P4 | `site/content/*.md` — the seven pages of prose | `PG-2`, `PG-3`, `PG-13`, `PG-15` | Each page's body has no bare percentage (`PG-9`) |
| P5 | `site/static/` — CSS, JS, icons | `AX-1`…`AX-9`, `NAV-3`, `NAV-4` | Contrast and target size measured, not declared |
| P6 | `site/check.py` | `PG-6`, `PF-5`, `SEO-3`, `SEO-4` | A planted broken link, a planted `alt="screenshot"`, a planted `94%` each fail the build |
| P7 | `site/shots.py`, `specs/008-github-page/e2e/`, workflow | `PG-14`, `AX-*`, `PF-*`, `11` | Every route screenshotted at four widths, both themes, and **looked at** |

## Phase 1. The licence and the front door

**Files:** `LICENSE` (Apache-2.0, verbatim, with the copyright line), `README.md` (rewritten).

The README is not the site. It is the *text version* of the site: same order, same three claims, same
screenshot, and a link to the site for anyone who wants the rendered version. Written for the reader who
arrives from a GitHub search and never leaves GitHub.

| Section | Content | Requirement |
|---|---|---|
| 1 | One paragraph: what OpenGenie is, what it is built from, Apache-2.0 | `PG-1`, `PG-12` |
| 2 | One screenshot, 1440 px, with its caption | `PG-3` |
| 3 | The three claims, each with a path | `PG-2` |
| 4 | The one measurement, with its caveat | `CPT-2` |
| 5 | Install in three commands | `PG-4` |
| 6 | What the repository contains, by directory | — |
| 7 | The study: what was measured, and its limits, linking `docs/` | `PG-15`, `PG-16` |
| 8 | Licence, author, how to contribute | `PG-12`, `PG-13` |

Nothing from the current README is deleted. The study content moves below the fold, where it belongs,
and every table stays generated by `exams/inject_tables.py`.

## Phase 2. `claims.py`

```python
def compute() -> list[Claim]: ...
```

Reads `exams/results/*/*.json` with the **same** skip predicate and the **same** denominator rule as
`exams/make_tables.py`, and returns the eight claims in [12](12-claims-ledger.md).

Acceptance, as a test (`site/tests/test_claims.py`):

1. `CL-3.value == 86` and `CL-3.numerator == 130` and `CL-3.denominator == 152`.
2. Every claim's `sources` list names files that exist.
3. A synthetic results directory containing only `_rejected` files yields zero claims and the code says
   so, rather than raising.
4. Rounding is idempotent: rendering a claim twice gives the same string.

This is the phase where a mistake is cheapest and most damaging, so it is the phase with the most tests.

## Phase 3. The renderer

**`mdrender.py`** handles exactly the constructs these docs use, and fails loudly on the ones it does
not know. Its heading slugs follow GitHub's rule (`[NAV-8]`), so a link that works on GitHub works on the
site.

**`pages.py`** is one table:

```python
@dataclass(frozen=True)
class Route:
    path: str          # "" for home, "tour/", ...
    title: str
    description: str
    nav: str           # the nav key, for aria-current
    body: Callable[[Ctx], str]
```

**`build.py`** writes: eight routes, `sitemap.xml`, `robots.txt`, `site.webmanifest`, `assets/*`, and the
screenshots the content references. It writes nothing it did not first resolve (`[PF-7]`).

Acceptance: `python3 site/build.py && cp -R site/dist /tmp/a && python3 site/build.py && diff -r
/tmp/a site/dist` is empty except `dist/build.json`'s timestamp, which is passed in as an argument in the
reproducibility test (`[PG-11]`).

## Phase 4. The prose

Five content files, in the order of the home page's argument:

| File | Page | The one job |
|---|---|---|
| `home.md` | `/` | Answer *what is this and why* in the first two viewports |
| `tour.md` | `/tour/` | Show the app, 17 screenshots, captioned by width and theme |
| `evidence.md` | `/evidence/` | Eight claim cards, generated from `claims.py` |
| `install.md` | `/install/` | Three ways to run it, with what each needs |
| `about.md` | `/about/` | Who, why, and what else he builds (`author.py`) |

The tutorial and the reference section have **no** content file: they render `docs/tutorial.md` and the
reference list (`[PG-7]`, `[PG-8]`).

### Copy rules

Applied to every sentence, and checked in review rather than by a script:

| Rule | Example of the failure it prevents |
|---|---|
| No adjective that cannot be measured | "powerful", "seamless", "revolutionary" |
| No comparative without its baseline | "faster" → faster than *what*, on *which task* |
| No number without its denominator | "94%" → "94% (143/152), 8 tasks, one run" |
| No claim about Genie Code that is not in the repository | It is a closed product; belief is not evidence |
| Second person for the reader, first person for the author | "you name the folder"; "we measured tokens" |
| A limit gets its own sentence, not a clause | "We measured tokens, not money." Full stop. |

## Phase 5. The stylesheet

One file. Sections in this order, because the cascade is the design:

1. tokens (the shared nine from the app, plus the site's own)
2. reset and base type
3. layout: `.shell`, `.rail`, `.main`, the measure
4. components: `.claim`, `.shot`, `.table`, `.callout`, `.btn`
5. header, footer
6. the two media queries (`1100`, `860`) and the phone rules
7. `prefers-reduced-motion`, `forced-colors`

Acceptance is measured, not asserted: `shots.py` computes contrast from painted colours, measures target
sizes, checks for horizontal overflow at 320 px, and reads CLS (`[AX-1]`, `[AX-6]`, `[AX-7]`, `[PF-2]`).

## Phase 6. `check.py`

Eight passes. Each one exists because of a specific way a static site goes wrong.

| Pass | Catches | Requirement |
|---|---|---|
| `--links` | A `href` to a route that was never built; an anchor to a heading that was renamed | `PG-6`, `NAV-1`, `NAV-8` |
| `--markup` | An unclosed `<div>`; a second `<h1>`; a skipped heading level | `PF-5`, `AX-2` |
| `--images` | A missing file; `alt="screenshot"`; a missing `width`/`height` | `AX-3`, `PF-2`, `PF-6` |
| `--claims` | A `{{CL-n}}` that was never substituted; a bare `\d+%` in prose | `PG-9`, `CPT-1` |
| `--meta` | A duplicate title; a missing canonical; JSON-LD that does not parse | `SEO-1`, `SEO-4` |
| `--sitemap` | A route missing from `sitemap.xml`, or a URL that does not exist | `SEO-3` |
| `--files` | No `LICENSE`; no `favicon`; no OG image at the declared size | `PG-12`, `SEO-2` |
| `--tokens` | The nine shared CSS values drifting from the app's stylesheet | `D6` |

Each pass has a **negative test**: a fixture that it must reject. A checker without a failing fixture is
a checker that might be returning 0 unconditionally.

## Phase 7. Screenshots, inspection, deployment

`shots.py` drives Playwright over the built site served by `python3 -m http.server`:

| Scene | Sizes | Files |
|---|---|---|
| Every route | 1440, 1100, 860, 390 | `<route>-<width>.png` |
| Home, dark | 1440, 390 | `home-1440-dark.png` |
| The three claims, cropped | 1440 | `home-claims.png` |
| A claim card, cropped | 1440 | `evidence-card.png` |
| The menu open | 860, 390 | `nav-open-<width>.png` |
| Theme control, three states | 1440 | `theme-system.png`, `theme-light.png`, `theme-dark.png` |
| JavaScript disabled | 1440 | `no-js-home.png` |
| Images blocked | 1440 | `no-img-home.png` |
| 404 | 1440 | `404.png` |

Plus one JSON per run: `audit.json` with contrast ratios, target sizes, CLS, overflow and the byte weight
of each page. The screenshots are committed under `specs/008-github-page/e2e/` so the evidence for the
page lives beside its specification, exactly as `specs/006-databricks/e2e/` does for the app.

**The inspection loop** ([10](10-e2e-plan.md)): open every image, name every defect, fix it, re-run only
that scene. [11](11-outcome.md) records what the pictures found that the assertions did not.

## Phase 8. The workflow

`.github/workflows/site.yml`:

```yaml
on: { push: { branches: [main] }, workflow_dispatch: {} }
permissions: { contents: read, pages: write, id-token: write }
jobs:
  build:
    steps: checkout → setup-python 3.12 → pip install -r requirements-site.txt
           → python site/build.py → python site/check.py
           → python site/tests/test_claims.py → upload-pages-artifact
  deploy:
    needs: build
    steps: deploy-pages
```

The check runs **before** the upload, so a broken page cannot replace a working one (`[PF-7]`).

## What each phase can break, and the test that catches it

A plan without this table is a plan that assumes the phases are independent. They are not: `claims.py`
feeds the prose, and the prose feeds the check.

| A change in | Can break | Caught by |
|---|---|---|
| `claims.py` | Every page that renders a claim | `test_claims.py` + `check.py --claims` |
| `mdrender.py` | Every anchor in the reference section | `check.py --links --markup` |
| `page()` in `build.py` | Every page's `<head>` | `check.py --meta` (7 routes at once) |
| `site.css` | Contrast in one theme but not the other | `shots.py`, both themes |
| `content/*.md` | A link, a claim, an anchor | `check.py` |
| A screenshot being recaptured | An `alt` that describes the old image | Manual, in the inspection loop |

## Definition of done

1. `python3 site/build.py && python3 site/check.py` exits 0.
2. Every requirement in [03](03-requirements.md) has a tick in [11](11-outcome.md) and a test or a
   screenshot behind it.
3. Every screenshot in `e2e/` has been opened and either accepted or fixed. The count of defects found
   by pictures is recorded in [11](11-outcome.md#what-the-screenshots-found-that-the-assertions-did-not).
4. The repository root has `LICENSE`, a README whose first screen answers the four questions, and a
   `specs/008-github-page/` set whose internal links all resolve (`verify-spec-links.mjs`).
